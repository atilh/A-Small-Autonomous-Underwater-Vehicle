# dvltest1：AUV 飞控与 DVL 联合控制程序

`dvltest1.py` 是一个面向真实 AUV/ROV 平台的 Python 控制程序。它通过 MAVLink 与 Pixhawk/ArduSub 类飞控通信，通过 TCP 接收 DVL（多普勒测速仪）的局部位置数据，并提供手动推进器控制、PID 定深、航向调整、航点前进和拍照等任务能力。

> [!CAUTION]
> 本程序会连接真实飞控，并在初始化阶段连续发送解锁指令。只有在载具已固定、推进器已拆除或采取其他可靠安全措施后，才能运行。首次调试应在无动力环境中完成。

## 主要功能

- 监听 MAVLink UDP 数据并连接 Pixhawk 飞控；
- 读取飞控的航向和深度数据；
- 通过 TCP 连接 DVL，读取 `position_local` 局部位置；
- 使用 PID 控制垂直推进器，实现自动定深；
- 通过 RC Override 控制升降、偏航和前后运动；
- 支持手动模式和自动航点模式；
- 自动航段通过定深、调航向、重置 DVL、前进和任务执行等状态运行；
- 支持滚转、转向、上浮和拍照等航点任务；
- 当前进距离长时间不变时，自动提高推进器输出以尝试脱困。

## 系统组成

```text
操作员终端
    │
    ├── 键盘指令 ───────────────┐
    │                           ▼
    │                    dvltest1.py
    │                     ├─ 控制状态机
    │                     ├─ 深度 PID
    │                     └─ RC/姿态指令
    │                           │
    ├── DVL TCP 数据 ───────────┤
    │                           ▼
    └──────────────────── Pixhawk / AUV
                         MAVLink UDP
```

程序启动后会创建五个后台线程，分别负责 DVL 数据读取、飞控数据读取、深度控制、主控制状态机和控制指令发送。

## 环境要求

### 硬件

- Pixhawk 或兼容 MAVLink 的飞控；
- 能输出局部位置数据并支持航位推算重置命令的 DVL；
- 与飞控、DVL 网络互通的运行设备；
- 根据任务需要配置的相机。

### Python 依赖

程序使用 Python 3，并依赖以下第三方包：

```bash
python -m pip install pymavlink opencv-python
```

此外，`dvltest1.py` 还依赖三个项目自定义模块：

| 模块 | 程序使用的接口 | 用途 |
| --- | --- | --- |
| `ticop` | `sleep_ms()` | 毫秒级休眠 |
| `pai` | `snap()` | 拍照并返回图片路径 |
| `ph` | `a_jpg()`、`b_jpg()`、`c_jpg()` | 执行三类图像任务 |

这些模块当前不在本目录中。运行前需要将对应的 `.py` 文件或可导入的软件包放入 Python 搜索路径，并确认其硬件接口与本机相符。

## 默认通信与控制参数

以下参数直接写在 `AdvancedAUVControl.__init__()` 中，部署前应按实际设备修改：

| 项目 | 默认值 | 说明 |
| --- | --- | --- |
| MAVLink 地址 | `udpin:0.0.0.0:14553` | 在本机 UDP 14553 端口等待飞控心跳 |
| DVL 地址 | `192.168.137.3:16171` | 主动建立 TCP 连接 |
| 垂直推进通道 | 索引 `2` | 传入 MAVLink 时对应 RC 通道 3 |
| 偏航通道 | 索引 `3` | 传入 MAVLink 时对应 RC 通道 4 |
| 前进通道 | 索引 `4` | 传入 MAVLink 时对应 RC 通道 5 |
| PWM 范围 | `1100–1900` | `1500` 为中性值 |
| 初始模式 | `manual` | 启动后默认手动控制 |
| 默认目标深度 | `0.1 m` | 正数表示水下深度 |
| 航点距离容差 | `0.10 m` | 判断航点到达的阈值 |
| 航向容差 | `3°` | 判断航向调整完成的阈值 |
| 深度容差 | `0.1 m` | 判断深度调整完成的阈值 |

代码中预置了一个航点：保持启动时读取的航向，前进 `0.5 m`，目标深度为 `0.2 m`。

## 运行前检查

1. 固定载具并确保推进器不会造成人员或设备伤害。
2. 确认飞控已向本机 UDP `14553` 端口发送 MAVLink 数据。
3. 确认 DVL 可从运行设备访问，且 TCP 地址为 `192.168.137.3:16171`；否则先修改代码中的 `dvl_ip` 和 `dvl_port`。
4. 确认 DVL 输出以 `\r\n` 分隔的 JSON 消息，并至少包含以下局部位置格式：

   ```json
   {"type":"position_local","x":0.42,"y":-0.08}
   ```

5. 确认 DVL 能接收以下航位推算重置命令，并返回响应：

   ```json
   {"command":"reset_dead_reckoning"}
   ```

6. 补齐 `ticop`、`pai` 和 `ph` 模块。
7. 核对 RC 通道映射、PWM 方向、深度正负号及飞控模式编号。

## 启动程序

```bash
python dvltest1.py
```

程序会依次执行以下操作：

1. 倒计时 5 秒；
2. 等待 Pixhawk 心跳；
3. 发送飞控模式和解锁指令；
4. 等待解锁成功；
5. 连接 DVL；
6. 读取一次当前航向作为初始目标航向；
7. 启动各控制线程并显示交互菜单。

如果飞控没有心跳、无法解锁，或 DVL 地址不可达，初始化会阻塞或直接报错。

## 交互控制

### 通用命令

| 按键 | 功能 |
| --- | --- |
| `m` | 切换手动/自动模式；进入自动模式时启用定深控制 |
| `g` | 将升降、偏航和前进通道恢复为 `1500` |
| `q` | 停止运动并退出程序 |

### 手动模式

| 按键 | 功能 | 默认 PWM/变化量 |
| --- | --- | --- |
| `w` / `s` | 上升 / 下降 | `1700` / `1450` |
| `a` / `d` | 左转 / 右转 | `1300` / `1700` |
| `e` / `c` | 前进 / 后退 | `1700` / `1300` |
| `i` / `k` | 目标俯仰增加 / 减少 | 每次 `10°` |
| `j` / `l` | 目标滚转减少 / 增加 | 每次 `10°` |
| `u` / `o` | 目标偏航减少 / 增加 | 每次 `10°` |
| `r` | 将目标滚转、俯仰和偏航重置为 `0°` | — |
| `=` | 调用 `snap()` 拍照 | — |
| `b` | 输入自定义目标深度 | — |
| `p` | 输入三个自定义 PWM 值 | `1100–1900` |

`z` 和 `x` 在当前实现中只会修改内部变量 `mo`，尚未形成完整、可直接说明的控制流程。菜单中显示的 `v` 命令没有对应处理分支。

### 自动模式

| 按键 | 功能 |
| --- | --- |
| `s` | 交互输入航向、距离和深度，生成航点列表 |
| `c` | 清空交互设置的航点 |
| `d` | 修改目标深度 |
| `e` | 启动交互设置的航点任务 |

自动航点状态机的执行顺序如下。首次启动或交互设置航点后，状态会从 `adjust_heading` 开始；切换到后续航点时，则先进入 `adjust_depth`。进入自动模式后，定深 PID 在线程中独立运行。

```text
首次/重新设置 ───────────────┐
                             ▼
后续航点 → adjust_depth → adjust_heading ── 航向调整超过 8 秒时继续
    ↓
reset_dvl
    ↓
move_forward ─── 前进超过 20 秒时跳过当前航点
    ↓
do_tasks（可选）
    ↓
下一个航点 / 任务完成并解除武装
```

## 航点与任务格式

代码支持简单元组航点：

```python
(目标航向, 前进距离, 目标深度)
```

也支持带任务的字典航点：

```python
{
    "h": 90.0,
    "d": 2.0,
    "z": 0.8,
    "tasks": ["photo", "turn"]
}
```

可用任务名称如下：

| 任务名 | 行为 |
| --- | --- |
| `roll` | 暂停定深，执行约两圈滚转，然后恢复定深 |
| `turn` | 分步设置 `0°–90°` 的目标偏航 |
| `photo` | 调用 `snap()` 拍照 |
| `mod` | 将目标深度设为 `0.5 m` 并等待 15 秒 |
| `a` / `b` / `c` | 调用对应图像函数，然后执行一次俯仰动作 |

## 关键实现说明

- 飞控数据：从 `VFR_HUD.heading` 读取航向，从 `AHRS2.altitude` 读取深度。
- 深度符号：控制线程使用 `-current_depth` 作为实际水下深度，部署时必须确认飞控坐标系与该约定一致。
- 深度控制：PID 输出叠加到中性 PWM `1500`，最终由 `set_channel()` 限制在 `1100–1900`。
- 前进控制：根据剩余距离进行比例控制；若剩余距离连续约 3 秒变化不足 `0.05 m`，程序逐步增加前进或后退输出。
- 姿态控制：自动模式以 20 Hz 发送 `SET_ATTITUDE_TARGET`，同时持续发送 RC Override。
- 任务结束：完成全部预置航点后将 `ok` 置为 `1`，发送解除武装命令。

## 当前版本注意事项

- 初始化会自动解锁飞控，且发送了三次解锁命令；这不是仿真安全默认值。
- `q` 退出主要停止线程并将相关 PWM 设为中性值，不保证退出前一定成功解除武装。
- 交互输入的航点写入 `self.waypoints`，而自动控制实际读取初始化时保存的 `self.waypoints_use`；如需在运行中动态更新航点，应同步更新这两个变量。
- `g` 只把控制通道恢复到中性值；在自动模式下，后台控制循环可能再次写入控制量。
- 飞控和 DVL 连接在对象初始化阶段同步建立，当前没有连接超时、重连或优雅降级机制。
- 多个线程共享姿态、深度和通道数据，除 DVL 位置外多数共享状态没有加锁。
- `PIDController.compute()` 未对极小或为零的 `dt` 做保护，极端情况下可能出现除零问题。
- `cv2`、`os`、`sys` 以及 `depth_pid` 在当前文件中未被实际使用，可在确认无外部依赖后清理。

## 建议的首次调试顺序

1. 不接推进器，仅验证 Python 依赖和自定义模块能否导入。
2. 使用 MAVLink 仿真或台架飞控验证心跳、模式切换和通道映射。
3. 使用模拟 DVL TCP 服务验证 JSON 分帧、位置读取和重置响应。
4. 在解除动力的实机上检查深度正负号、PWM 方向和急停行为。
5. 在受控水池中从低推力、短距离的单航点任务开始测试。
